## 二、说明

管廊监测节点系统软件 V1.0适用于工业物联网、城市基础设施安全监测场景。用户进入系统后，可以围绕实际工作内容完成账号进入、业务创建、过程查看、结果确认和资料管理等操作。

日常使用时，城市管廊运维管理单位、市政基础设施监控中心、智慧城市平台运营方、工业安全监测服务商可以按照页面提示从入口进入相应页面，查看当前业务状态，并根据页面中的按钮、输入框、列表或弹窗继续处理。实现地下管廊内甲烷浓度、火焰、氧气、温湿度、三相电流、水流量、应力和位移等环境参数的实时采集和自动上报，保障管廊运行安全，预防气体泄漏、火灾和结构异常等安全隐患。系统采用以太网本地连接监控中心服务器，数据传输在局域网内完成，避免数据外泄风险；同时配置 LoRa 和ESP8266 WiFi作为备用通信链路，确保主链路故障时数据仍能上报，保障监测数据不丢失。

基于 STM32 嵌入式平台的城市地下管廊环境安全监测系统，集成多传感器数据采集、实时数据处理和多链路通信上报功能。

本软件是面向城市地下管廊环境安全监测的嵌入式系统软件，运行于 STM32H743XI 微控制器，基于 RT-Thread 实时操作系统。软件通过集成甲烷传感器、火焰传感器、氧气传感器、温湿度传感器以及 Modbus 工业总线设备，实现对管廊内环境参数和设备运行状态的实时采集，并通过以太网、LoRa或 MQTT 方式将数据上报至监控中心，为管廊运维管理提供数据支撑。

软件主要面向城市管廊运维管理单位、市政基础设施监控中心和智慧城市平台运营方。通过部署在管廊现场的监测节点设备，运维人员能够远程掌握管廊内的气体浓度、温湿度、电力负荷、水流量和结构应力等关键参数，及时发现气体泄漏、火灾隐患和结构异常，降低安全事故风险。

软件采用多线程并发架构，各传感器采集线程、Modbus主站轮询线程和网络上报线程独立运行，互不阻塞。甲烷传感器采集线程通过 UART2 数据通道读取19字节数据帧，解析 PPM 浓度值和 LEL 百分比，采样周期可配置。火焰传感器采集线程使用 ADC1 的五个通道，对应五路火焰探头的模拟输出，原始 ADC 值范围0至4095，支持多点火情监测。

氧气传感器采集线程使用 ADC1 通道18，将模拟电压线性转换为氧气百分比，并内置空气稳定化逻辑，当读数接近空气中氧气含量时自动校准至20.9%。温湿度传感器采集线程通过 I2C1 总线读取 SHT30 传感器数据，执行 CRC8 校验确保数据可靠性，I2C通信失败时保留上次有效值并记录错误。

本手册用于说明软件的用途、功能特点、运行要求和页面操作流程。各功能章节按用户能够看到的页面、入口、按钮、输入项、提示信息和处理结果进行说明。

## 三、功能特点

用户可在系统启动与初始化页面完成硬件初始化和线程启动，使监测节点进入正常工作状态。页面上的串口终端输出 RT-Thread 启动日志、显示内核版本号和编译日期、输出各线程创建成功的提示和输出设备初始化状态会集中呈现当前可操作内容，用户处理完成后可以看到串口终端输出初始化完成提示、LED指示灯显示系统运行状态和网络连接成功后输出 TCP 连接日志。

在甲烷浓度监测页面中，用户主要处理实时监测管廊内甲烷气体浓度，预防燃气泄漏和爆炸风险。系统把串口终端输出甲烷浓度 PPM 值、输出 LEL 百分比（爆炸下限百分比）、输出告警状态标志和 JSON 数据包中包含methane_ppm和methane_lel字段放在当前操作区域，处理结束后会反馈串口实时输出：gas:XXX.X ppm, level: XX%, alarm:0xXX、数据通过网络上报至监控中心和监控中心根据阈值判断是否触发告警。

火焰传感器监测页面关注的是监测管廊内五个位置的火情，及时发现火灾隐患。用户通过串口终端输出五路 ADC 通道的原始值、显示CH0、CH1、CH3、CH4、CH5各通道读数和 JSON 数据包中包含 ch0 至 ch5 字段和 flame 字段确认当前状态，并在操作结束后获得串口实时输出：ADC CH0: XXXXX CH1: XXX CH3: XXX CH4: XXX CH5: XXX、flame字段为1表示检测到火焰，为0表示无火焰和监控中心收到火焰告警后通知运维人员处理。

用户可在氧气浓度监测页面监测管廊内氧气浓度，预防缺氧或富氧风险。页面上的串口终端输出氧气浓度百分比和 JSON 数据包中包含 o2 字段会集中呈现当前可操作内容，用户处理完成后可以看到串口实时输出氧气浓度，例如：O2: 20.9%、数据通过网络上报，监控中心根据阈值判断是否告警和缺氧或富氧时禁止人员进入管廊。

在温湿度监测页面中，用户主要处理监测管廊内环境温度和湿度，评估环境舒适性和设备运行条件。系统把串口终端输出温度（摄氏度）和湿度（相对湿度百分比）和 JSON 数据包中包含 temperature 和 humidity 字段放在当前操作区域，处理结束后会反馈串口实时输出：Temperature: XX.X C, Humidity: XX.X %RH、I2C通信失败时输出错误日志和数据通过网络上报至监控中心。

电表数据采集页面关注的是通过 Modbus 协议采集三相电表的电压和电流数据，监控管廊内电力负荷。用户通过串口终端输出三相电压值（voltage_a、voltage_b、voltage_c）、输出三相电流值（current_a、current_b、current_c）、显示 Modbus 寄存器原始值和 JSON 数据包中包含电压和电流字段确认当前状态，并在操作结束后获得串口实时输出：[Ammeter] Voltage[0]: XXX.XX V, Current[0]: X.XXX A、Modbus通信成功时显示寄存器原始值和通信失败时输出错误码。

用户可在水表流量采集页面通过 Modbus 协议采集水表流量数据，监控管廊内供排水系统运行状态。页面上的串口终端输出水流量值（单位通常为立方米每小时）和 JSON 数据包中包含 flow 字段会集中呈现当前可操作内容，用户处理完成后可以看到串口实时输出：[Water] Flow: X.XXX、Modbus通信失败时输出错误日志和数据通过网络上报，监控中心根据流量变化判断是否异常。

在应力传感器监测页面中，用户主要处理监测管廊结构的应力变化，预防结构变形和坍塌风险。系统把串口终端输出应力值（单位：牛顿N，保留两位小数）和 JSON 数据包中包含 stress 字段放在当前操作区域，处理结束后会反馈串口实时输出应力值，例如：Stress: X.XX N、Modbus通信失败时输出错误日志和数据通过网络上报，监控中心根据应力变化趋势评估结构安全。

## 五、系统启动与初始化

用户可在系统启动与初始化页面完成硬件初始化和线程启动，使监测节点进入正常工作状态。用户可以通过 MCU 上电后自动启动 RT-Thread 操作系统，执行 main 函数。

设备上电或复位后自动执行，无需人工干预。

用户在系统启动与初始化页面会看到串口终端输出 RT-Thread 启动日志、显示内核版本号和编译日期、输出各线程创建成功的提示和输出设备初始化状态等信息，并可依据页面显示继续处理。

使用该功能时，用户先 MCU 上电，运行 bootloader 并加载固件，随后 RT-Thread 内核启动，初始化时钟和内存，接着创建传感器采集线程（甲烷、火焰、氧气、温湿度），之后创建 Modbus 主站轮询线程和数据发送线程，再初始化以太网数据通道，配置静态IP，继续创建网络上报线程（以太网、LoRa、MQTT），最后各线程进入周期性运行状态。

页面会按照硬件必须正确连接传感器和通信模块、供电电压必须稳定在正常范围和网络配置必须与监控中心匹配等规则限制或提示用户。处理结束后，用户可以看到串口终端输出初始化完成提示、LED指示灯显示系统运行状态和网络连接成功后输出 TCP 连接日志。

## 六、甲烷浓度监测

用户可在甲烷浓度监测页面实时监测管廊内甲烷气体浓度，预防燃气泄漏和爆炸风险。用户可以通过系统启动后自动运行甲烷传感器采集线程。

系统运行期间自动监测，当管廊内存在燃气管道或有可燃气体泄漏风险时使用。

该部分提供串口终端输出甲烷浓度 PPM 值、输出 LEL 百分比（爆炸下限百分比）、输出告警状态标志和 JSON 数据包中包含methane_ppm和methane_lel字段等页面内容，用户可据此查看状态、填写信息或选择下一步操作。

在该页面中，用户先甲烷传感器通过 UART2 数据通道周期性发送19字节数据帧，随后采集线程接收数据帧并验证帧头（0xAC 0xAC），接着计算并校验数据帧的校验和，之后解析 PPM 浓度值和 LEL 百分比，再将数据存储到全局变量供上报模块使用，最后串口输出当前读数和告警状态。

如果不满足数据帧必须以0xAC 0xAC开头、校验和必须正确，否则丢弃该帧、PPM值超过预设阈值时产生告警和 LEL 百分比超过一定比例视为危险状态等要求，用户需要根据页面提示调整后再继续。页面反馈通常包括串口实时输出：gas:XXX.X ppm, level: XX%, alarm:0xXX、数据通过网络上报至监控中心和监控中心根据阈值判断是否触发告警。

## 七、火焰传感器监测

用户可在火焰传感器监测页面监测管廊内五个位置的火情，及时发现火灾隐患。用户可以通过系统启动后自动运行火焰传感器采集线程。

系统运行期间自动监测，覆盖管廊内关键区域的火焰探测。

页面上主要呈现串口终端输出五路 ADC 通道的原始值、显示CH0、CH1、CH3、CH4、CH5各通道读数和 JSON 数据包中包含 ch0 至 ch5 字段和 flame 字段等内容，这些内容用于帮助用户确认当前位置和可执行操作。

实际操作时，用户先 ADC 采集线程每500毫秒触发一次采集，随后依次读取 ADC1 的五个通道（对应五路火焰传感器），接着获取12位 ADC 原始值（范围0至4095），之后将原始值存储到全局变量，再根据阈值判断是否检测到火焰，最后更新 flame 状态标志。

操作过程中需要注意 ADC 值范围为0至4095、无火焰时 ADC 值通常低于500、有火焰时 ADC 值显著升高至2000以上和多路同时检测到异常时可提高告警等级。操作完成后，系统会显示串口实时输出：ADC CH0: XXXXX CH1: XXX CH3: XXX CH4: XXX CH5: XXX、flame字段为1表示检测到火焰，为0表示无火焰和监控中心收到火焰告警后通知运维人员处理。

## 八、氧气浓度监测

用户可在氧气浓度监测页面监测管廊内氧气浓度，预防缺氧或富氧风险。用户可以通过系统启动后自动运行氧气传感器采集线程。

系统运行期间自动监测，保障人员进入管廊时的安全。

用户在氧气浓度监测页面会看到串口终端输出氧气浓度百分比和 JSON 数据包中包含 o2 字段等信息，并可依据页面显示继续处理。

使用该功能时，用户先氧气传感器采集线程每2秒读取一次 ADC1 通道18，随后将 ADC 原始值转换为毫伏（mV），接着根据线性公式将电压转换为氧气百分比，之后应用空气稳定化逻辑，读数接近20.9%时自动校准，再将氧气浓度存储到全局变量，最后串口输出当前读数。

页面会按照正常空气中氧气浓度约为20.9%、浓度低于19.5%视为缺氧环境、浓度高于23.5%视为富氧环境和空气稳定化范围为20.7%至21.1%等规则限制或提示用户。处理结束后，用户可以看到串口实时输出氧气浓度，例如：O2: 20.9%、数据通过网络上报，监控中心根据阈值判断是否告警和缺氧或富氧时禁止人员进入管廊。

## 九、温湿度监测

用户可在温湿度监测页面监测管廊内环境温度和湿度，评估环境舒适性和设备运行条件。用户可以通过系统启动后自动运行温湿度传感器采集线程。

系统运行期间自动监测，为管廊环境评估提供数据。

该部分提供串口终端输出温度（摄氏度）和湿度（相对湿度百分比）和 JSON 数据包中包含 temperature 和 humidity 字段等页面内容，用户可据此查看状态、填写信息或选择下一步操作。

在该页面中，用户先温湿度采集线程通过 I2C1 总线与 SHT30 传感器通信，随后发送单次测量命令（0x2C 0x06），接着延时等待传感器完成测量（约15毫秒），之后读取6字节响应数据（温度2字节+CRC1字节+湿度2字节+CRC1字节），再验证 CRC8 校验码确保数据可靠，继续将原始数据转换为摄氏度和相对湿度百分比，最后 I2C 通信失败时保留上次有效值并记录错误。

如果不满足 I2C 设备地址为0x44、CRC8校验必须通过，否则丢弃该次读数、温度范围通常为-40℃至125℃和湿度范围为0%至100%RH等要求，用户需要根据页面提示调整后再继续。页面反馈通常包括串口实时输出：Temperature: XX.X C, Humidity: XX.X %RH、I2C通信失败时输出错误日志和数据通过网络上报至监控中心。

## 十、电表数据采集

用户可在电表数据采集页面通过 Modbus 协议采集三相电表的电压和电流数据，监控管廊内电力负荷。用户可以通过系统启动后自动运行 Modbus 主站轮询线程。

系统运行期间自动轮询，了解管廊内照明、通风等用电设备的运行状态。

页面上主要呈现串口终端输出三相电压值（voltage_a、voltage_b、voltage_c）、输出三相电流值（current_a、current_b、current_c）、显示 Modbus 寄存器原始值和 JSON 数据包中包含电压和电流字段等内容，这些内容用于帮助用户确认当前位置和可执行操作。

实际操作时，用户先 Modbus 主站轮询线程每500毫秒触发一次，随后向电表从站（地址2或73）发送读保持寄存器请求，接着读取电压寄存器（起始地址0x100，共6个寄存器），之后读取电流寄存器（起始地址0x10E，共6个寄存器），再每个数值由2个16位寄存器组成32位浮点数（大端序），继续将寄存器数据转换为浮点数并存储到全局变量，最后串口输出电压和电流读数。

## 十六、常见问题解答

问题：设备上电后串口无输出怎么办？
解决方法：首先检查串口线是否正确连接到 UART1 引脚，确认 TX 和 RX 没有接反。然后检查串口终端软件的参数配置，波特率必须设置为115200、8数据位、无校验、1停止位。如果仍无输出，使用万用表测量设备供电电压是否正常，确认固件是否已正确烧录。

问题：以太网无法连接到监控中心服务器怎么办？
解决方法：首先通过串口查看 PHY 链路状态，确认显示link up和100Mbps full-duplex。然后检查网线连接是否正常，网口指示灯是否亮起。确认设备 IP 地址192.168.1.30与监控中心 IP 地址192.168.1.100在同一网段，网关和子网掩码配置正确。在 PC 上使用 ping 命令测试是否能 ping 通设备IP，如果不通则检查网络拓扑和交换机配置。确认监控中心服务器已启动 TCP 监听服务，监听端口为8080。

问题：Modbus设备读取失败怎么办？
解决方法：首先检查 RS485 总线的A、B线是否正确连接，确认没有接反或短路。然后通过串口查看 Modbus 通信日志，确认从站地址、波特率、校验位和停止位配置是否与实际设备匹配。电表从站地址通常为2或73，水表为1，应力传感器为3。波特率通常为9600，无校验，1停止位。如果多个设备共享同一 RS485 总线，确认各设备从站地址不冲突。检查 RS485 模块的供电和使能信号是否正常。

问题：某个传感器数据一直为0或异常怎么办？
解决方法：通过串口输入list_thread命令查看对应传感器的采集线程是否正常运行。如果线程挂起或未启动，检查代码中是否有初始化失败。输入list_device命令查看对应设备是否已注册。对于 ADC 传感器，确认引脚连接正确，传感器供电正常。对于 I2C 传感器，使用示波器或逻辑分析仪检查 SCL 和 SDA 信号波形，确认 I2C 地址正确。对于 UART 传感器，确认波特率和数据格式匹配。检查传感器本身是否损坏，必要时更换传感器测试。

问题：如何修改数据上报周期？
解决方法：数据上报周期在源代码的头文件中定义。以太网上报周期在 ethApp.h 中定义，LoRa上报周期在 loraApp.h 中定义。修改对应宏定义的数值（单位通常为毫秒），重新编译固件并烧录到设备。修改后通过串口查看上报日志的时间间隔，确认修改生效。不建议将周期设置过短，避免网络拥塞或设备功耗过高。

问题：如何查看设备运行时间和内存使用情况？
解决方法：通过串口连接设备，在 MSH 命令行中输入 free 命令可以查看当前内存使用情况，包括总内存、已用内存、剩余内存和内存碎片。输入list_thread命令可以查看各线程的栈使用情况和运行时间统计。如果发现内存不足，可能是某个线程栈溢出或存在内存泄漏，需要检查代码并优化内存分配。
